# ADR 0015 — Surface unbounded full-column SUMIFS (D1 portability detector)

**Status:** Accepted — 2026-06-22
**Track:** formula-portability (unbounded full-column SUMIFS)

## Context

A SUMIFS-family formula whose sum or criteria range is a full COLUMN (`$AC:$AC`, `A:A`, `A:AD`)
computes correctly while the workbook is LIVE in Workiva, but throws `#VALUE!` when the workbook is
exported to xlsx and reimported or rolled forward (a documented bounding fix recipe exists).
Field history records this as the single most frequent Workiva portability defect —
thousands of cells on a single engagement alone. The defect
is latent: every live tieout and numeric check passes, so it survives undetected until next year's
roll-forward or any round-trip through Excel, then breaks with no audit trail.

The proven detection and remediation already exist outside Wingman:
the external checks toolkit's `bound_sumifs.py` (a gated write-plan generator that binds every
full-column range to a uniform ceiling `M`, value-preserving when `M >= the data extent`) and
`corpus_audit.py`'s `unbounded_rng` detector (`RE_FULLCOL.search(f) and RE_SUMIF.search(f)`). Wingman
had no surface for it, so the latent debt was invisible at scan time.

## Decision

Add `formula_hygiene.detect_unbounded_sumifs` as the 4th Lane G detector — **surfaced only,
`fixable=False`** (consistent with the other three formula-hygiene detectors; a formula rewrite is a
Workiva write that lives behind the gated `bound_sumifs.py` apply, not in Wingman).

- **Gate:** for each SUMIFS-family call (`_IFS_FUNC`: SUMIFS/COUNTIFS/AVERAGEIFS/MAXIFS/MINIFS), the
  argument list is parsed with the existing `_arg_list` and each argument is tested for a full-column
  range (`_FULLCOL_RANGE = \$?[A-Z]{1,3}:\$?[A-Z]{1,3}`, mirroring `bound_sumifs.RE_FULLCOL`) **after**
  stripping `'Sheet'!` refs and `"..."` string literals.
- **Severity** `medium` — latent reimport/roll-forward debt, not a live error (matches the
  `corpus_audit` weight of 2.0, below `sign_literal`/`dead_func`).
- **Per-sheet, not per-cell:** the `detail` is a single fixed string, so `detectors.group_findings`
  collapses every flagged cell on a sheet into one Review row (mirrors `bound_sumifs.py`'s per-sheet
  count). This is the explicit anti-noise requirement from the candidate hint.
- A `formula.unbounded-full-column-sumifs` diagnose pathway explains the latent #VALUE! risk and the
  bind-to-rows remediation, and points at the gated `bound_sumifs.py` write-plan + readback for the
  actual fix.

### Precision over the coarse corpus gate (deliberate divergence)

`corpus_audit`'s `unbounded_rng` uses a coarse whole-formula gate: full-column present **anywhere**
AND a SUMIFS-family call present **anywhere**. That over-fires on
`=SUMIFS($B$2:$B$100,$A$2:$A$100,B5)+INDEX(A:A,3)` — the bounded SUMIFS is fine and the full-column
`A:A` is in an `INDEX`, which is **not** the SUMIFS reimport defect. Wingman parses each SUMIFS
call's own argument list instead, so a full-column ref outside any IFS call never fires. This matches
the formula-hygiene module's existing FP-discipline (positional SUMIFS-criteria parsing, ROUND
paren-walks). Counts may therefore be slightly lower than the corpus audit's coarse total; that is
correct for the named defect.

## False-positive guards (tested)

- **Bounded ranges** (`$AC$2:$AC$100`, `$AC2:$AC100`) — a digit breaks the letter run, no match.
- **Quoted criterion that looks like a range** (`SUMIFS(...,"A:Z")`) — string literals stripped first.
- **Sheet name containing a colon** (`'Budget A:Z'!$B$2:$B$100`) — sheet refs stripped first.
- **Full-ROW range** (`$1:$1` header lookup) — no letters, not the `#VALUE!` risk, no match.
- **Full-column ref outside any IFS call** (`INDEX(A:A,…)`, `VLOOKUP(B1,A:D,2,0)`) — only IFS-call
  argument lists are inspected.

## Boundary

Read-only / surfaced. The detector reads normalized cell formulas already in the scan path and emits
a Review finding. It performs **no Workiva write** and proposes **no auto-rewrite** — the
value-preserving bounding is generated by `bound_sumifs.py` and applied only through the existing
gated live-apply with before/after readback proof.

## Alternatives considered

- **Auto-fix the bounding inside Wingman** — rejected. The rewrite is a Workiva write; it belongs
  behind the gated apply with readback, not in a scanner. `fixable=False` is the correct posture.
- **Reuse the coarse corpus gate verbatim** — rejected for the `INDEX(A:A)` false positive above.
- **Per-cell rows** — rejected; the candidate explicitly requires a per-sheet count to avoid a wall
  of noise on workbooks with thousands of full-column SUMIFS.
